## 1. 要交付的产品

桌面用户安装同一个 Bakabase。它始终能够管理本机资源，也能连接其他获准访问的设备。在任意一台桌面设备上，用户可以同时搜索本机和其他在线设备的资源，并在当前设备上查看、播放远端内容。

每台设备独立持有自己的数据库、文件和后台任务。联合视图由当前设备临时汇总，不设固定中心，不复制整个数据库，不自动在设备间搬运文件。

### 1.1 首个完整版本的用户验收场景

1. A、B 都安装统一桌面版；A 有 100 条本机资源，B 有 200 条。两边完成分享授权后，A、B 都能搜索两边的资源。资源 ID 相同不会互相覆盖。
2. C 是没有图形界面的 NAS 服务端。A 可以将 C 加入搜索范围；C 不需要为了分享资源安装桌面外壳。
3. A 本机没有资源，也能直接连接 B、C，使用联合媒体库；不要求先创建本机媒体库或导入文件。
4. A 搜到 B 上的视频，在 A 的播放器或预览窗口打开；B 上没有播放器进程被启动。
5. B 离线，A 的本机库与 C 继续可用。界面显示本次搜索未覆盖 B，不能把 B 的失败显示成“0 条资源”。
6. A 的本机管理功能保持可用。联合视图不允许删除、移动、改属性或触发远端下载；进入本机库后原有管理功能继续工作。
7. 原一体版、纯客户端和手机仍能连接升级后的服务端。现有用户不会因这次升级被静默换安装包、换数据目录、丢失配对或接收错误的更新包。

### 1.2 分期范围

| 本期必须完成 | 后续独立演进 |
|---|---|
| 桌面统一入口；本机空库可用 | 停止纯客户端维护的具体日期 |
| 多台设备直接连接、定向授权、分别撤销 | 账号体系、邀请整个家庭/组织、多级权限继承 |
| 在线联合搜索、稳定分页、来源标识、部分失败 | 离线目录持久缓存、离线编辑、元数据复制 |
| 自包含的只读资源详情、封面、文件型媒体预览/播放 | 远端属性编辑、删除、移动、下载任务调度 |
| 每设备路径映射；播放发生在当前设备 | 跨设备自动复制、空间均衡、资源迁移 |
| 兼容旧端；原有本机业务保持原入口 | 全局作品去重、多个副本合并、共享播放进度 |

“统一桌面端”不要求手机运行完整服务端，也不取消 Docker 的无界面部署。首期不新增 Linux 桌面发布、公网穿透或传输加密体系。

## 3. 本计划采用的默认决策

这些决定使工作包可以直接拆解。它们不是隐藏在实现中的默认行为；若评审调整其中一项，应先同步修改相关协议与验收，不边实现边猜。

| 编号 | 默认决策 | 原因与边界 |
|---|---|---|
| D01 | 统一桌面产品延续 `Bakabase` 包与数据目录 | 现有一体版自然升级，不另造第三个桌面产物 |
| D02 | 每台节点只权威管理自己的资源 | 无数据库多主写入、冲突合并和删除传播 |
| D03 | 只查询直接授权的节点；导出接口只返回本节点资源 | A→B 不代表 A→C，B 不递归查询它认识的节点 |
| D04 | 首期授权单位是“此节点全部本地资源的只读访问” | 文案明确包含元数据和已支持的媒体读取；不假装已实现按集合/属性的细粒度 ACL |
| D05 | 双向互访是两份独立定向授权 | 任一方向可独立拒绝/撤销；失败时保留清晰的单向状态 |
| D06 | 旧管理员配对和新资源分享授权分开 | 旧端行为不变，新节点凭据不能访问旧管理接口 |
| D07 | 联合视图只读，本机管理保持原流程 | 不把全部历史资源组件和业务写接口纳入首期重构 |
| D08 | 首期只查在线节点，不保存长期远端目录 | 离线状态可见；内存分页快照有明确 TTL |
| D09 | 同作品/同文件的多节点记录不自动合并 | 保留来源和独立身份，避免误删副本或混淆占位资源 |
| D10 | 不兼容的旧服务端不参与联合查询 | 仍可用既有客户端/浏览器访问；不偷偷降级到管理员 API 进行抓取 |
| D11 | 联合查询使用独立公共语义 | 自定义条件不支持就明确返回，不悄悄放宽查询 |
| D12 | 纯客户端先保留兼容和迁移入口，后收敛下载入口 | 先让新能力可用，再处理旧安装迁移，不强制卸载 |
| D13 | 联合页本机资源也使用公共筛选语义 | 需要本机全部高级筛选时切回本机库，切换前展示条件变化 |

产品评审重点是 D04、D07、D08、D10、D11：整库只读分享、远端暂不编辑、仅在线、不联合旧协议节点、公共筛选子集。本文以这些默认方案编排工作，技术参数不作为需要反复询问的事项。

## 4. 目标结构与模块改造

```text
Bakabase.App ──> Bakabase.Shell
      └───────> Bakabase.Service
                    ├─ 现有本机业务/数据库/任务
                    ├─ FederationLocalController：本机界面的管理、汇总与播放入口
                    ├─ FederationExportController：仅本节点的只读协议
                    ├─ 本机资源查询与资产解析适配器
                    └─ Bakabase.Modules.Federation
                           ├─ 节点目录、定向授权、连接与能力
                           ├─ 公共查询协议、查询会话、多路合并
                           └─ 依赖窄接口，不引用 Service/legacy/Shell

Bakabase.Modules.RemoteAccess：保留旧协议；提供可复用发现/签名基础能力
Bakabase.Modules.Player：本机播放器发现、播放启动等可复用能力
Bakabase.Client.Remoting：过渡期继续承载旧纯客户端，适配下沉后的基础能力
```

### 4.2 复用方式

1. 发现、握手 JSON、时钟解析、签名规范等独立于客户端宿主的代码下沉；先保留旧命名空间适配或委托，保证原测试锁定行为。
2. 新增 `IPeerSessionFactory.Get(NodeId)`，返回不可变的目标地址、授权、能力和时钟上下文。一次请求固定使用同一份上下文；地址更新、撤销不改变正在签名的目标。
3. 路径映射以来源节点为键。新播放器入口接收 `ResourceRef`/`AssetRef`，不依赖 `ActiveConnection`。
4. `Service` 不引用 `Client.Remoting`。YARP 若继续复用，只用于受控媒体传输，不把整站转发器挂进一体版。
5. 一体版本地 `BakabaseHost`、单实例标识、主页面与数据库仍是主线原有机制。不再启动一套旧 `ClientHost`，避免双容器、两套配置及端口冲突。
6. 新模块默认不对外分享，不自动打开远程访问。无人连接、功能未启用时不启动高频探测或扫描全库。

## 5. 身份、存储与资源引用

### 5.1 三种身份分别处理

- **NodeId**：一个资源库节点的持久身份。升级时继承现有 `RemoteAccessOptions.ServerId`，不使用 IP、机器名或设备平台作为身份。
- **LibraryEpoch**：业务库重建/替换/回滚恢复时变化的代际标识。防止旧的资源引用在新空库或旧备份恢复后重新使用数字 ID，指向另一条资源。正常重启、升级及不回滚数据的原库搬迁不变；恢复历史备份、清空重建必须换代；“作为另一台新设备恢复”还必须更新 NodeId。
- **GrantId**：某节点签发给某来访节点的单向授权身份。它不是 NodeId，也不是旧协议的 DeviceId。

建议传输形态：

```text
ResourceRef = { nodeId, libraryEpoch, resourceId }
AssetRef    = { resourceRef, assetId }
PeerRecord  = { nodeId, label, addresses, expectedLibraryEpoch,
                outboundGrantRef, inboundGrantRef, capabilities, pathMappings }
```

资源、属性和集合原表的数字主键不迁移成全局 GUID。跨设备的缓存键、选中状态、URL、详情参数都使用完整 `ResourceRef`。`ResourceSource` 继续表示内容来源，不能挪来表示所属设备。

作品的 `ThirdPartyId + ExternalId`、平台 `SourceKey` 可以用于展示和日后去重候选，但不能代替 ResourceRef，也不在首期自动合并资源。

### 5.2 持久化

新数据通过 `AppService.AppDataDirectory` 的目录适配器写入 `federation/`，目录在首次启用时创建。

| 文件/数据 | 内容 | 规则 |
|---|---|---|
| `node.json` | schemaVersion、NodeId、LibraryEpoch | 不进入 `[Options]` 广播；与已有 ServerId 建立单向一致性迁移 |
| `peers.json` | 已知地址、名称、配对方向、能力摘要、路径映射 | 地址可变，身份不可被新握手静默覆盖 |
| `grants.json` | 入站/出站授权、密钥、撤销状态和版本 | 原子写入；前端 DTO、日志、遥测、普通设置导出不包含密钥 |
| 内存查询会话 | 各节点快照、合并状态、已返回页 | 到期、撤销、关闭分享时清理；不纳入备份 |
| 本机界面偏好 | 搜索范围、视图布局、最后使用的设备 | 存本机；不覆盖远端的 LastSearch/SavedSearch |

新文件有 schemaVersion、原子写入和失败恢复。读取损坏凭据时明确报需要重新配对，不以随机新身份继续运行。恢复历史库时更新 LibraryEpoch，使旧查询/引用及绑定旧代际的入站分享授权失效；不能让备份里的旧授权无提示复活。“克隆为新节点”同时重置 NodeId、清除节点授权。支持的恢复入口必须实施此规则；绕过入口手工整体替换 AppData 无法保证自动识别，需提供显式的重置节点/库代际操作。

地址变化先发现候选，再用已知授权做挑战验证后更新地址。多个网卡地址不等于重复节点；若同一身份同时出现不同活动实例且无法确认是重启/地址切换，显示身份冲突并暂停自动选择。不能宣称可以可靠自动识别所有离线克隆，恢复向导必须提供显式的新节点选项。

## 6. 配对、权限与在线状态

### 6.1 新协议与旧管理员配对隔离

建议新签名方案标识 `Bakabase-Node`，独立的 principal、store 和授权对象；复用 HMAC 规范化、nonce、时间校正基础代码，但使用独立的签名域版本，避免与 `Bakabase-Device` 混用。

签名规范包含协议域、GrantId、请求方 NodeId、目标 NodeId、HTTP 方法、最终 path/rawQuery、timestamp、nonce 和 body digest。一次请求固定目标、凭据与时钟快照；不自动跟随跨主机重定向携带签名。不合法签名、过期凭据或错误目标不能降级匿名。

新授权只有两类能力：读取本机资源目录/元数据，以及读取协议明确提供的媒体资产。新增端点默认不获得授权。没有远端写操作、管理设置、读取任意路径、任意 HTTP 转发、再批准第三台设备的能力。

必须满足：

1. 所有导出端点独立验证节点签名、授权方向、当前分享状态、请求体及资源归属；回环来源和 Unrestricted 模式均不豁免。
2. 携带 `Bakabase-Node` 的请求在旧回环/Unrestricted 放行之前进入节点边界。请求旧 `/options`、`/resource` 写接口、`/hub/ui`、旧配对管理等一律拒绝，不回落为匿名或旧已配对身份。
3. 无凭据不能读取新导出端点。匿名只允许窄握手/发起配对/领取结果流程；批准和发码属于本机管理能力。
4. 协议控制请求有体积上限，并完整签名其实际请求体；不得沿用“过大或 chunked body 不验摘要”的退化行为。媒体 GET/HEAD 不缓冲整个文件。
5. 旧 `Bakabase-Device` 流程仍按旧约定工作。新能力不能暗中撤销已有手机/纯客户端的管理权限。
6. 新本机汇总和管理端点使用专门的本机访问守卫，验证 loopback、Host 和敏感操作的 Origin；不因为“已配对”而允许远端调用。

**管线衔接必须显式实现：**先按 route metadata 和 scheme 分派。新导出走独立分支，执行远程访问未关闭、分享开关、Node 签名/权限检查后，直接进入导出执行，不再让旧 Device 解析、RequirePairing 或旧 MVC filter 把它当匿名重判。本机接口走本机策略；旧接口继续原流程，任何携带新 scheme 的旧接口请求提前拒绝。可以用独立 branch pipeline 或明确的专用端点策略实现，但不得靠把 NodePrincipal 转成旧 `IsPaired=true` 解决集成问题。

**兼容性的实际边界：**旧 Unrestricted 或匿名可访问接口仍代表用户原来开放的权限。新节点凭据只读，并不能使已经匿名开放的旧接口变成私密。分享向导展示当前开放模式；不自动更改既有模式。新安装若只需配对访问，向导明确配置受限远程访问及 RequirePairing。新节点请求仍需单独的分享授权，不能从这些全局模式推导出来。

### 6.2 双向配对状态机

```text
未关联 → 发现/输入地址 → 校验身份与能力 → 请求读取对方
       → 等待对方批准/输入一次性码 → 出站授权已建立
       → 可选邀请对方读取本机 → 入站授权已建立 → 双向互访
```

一次用户流程可以编排两份授权，但分方向显示结果；反向不通时保留“我能访问对方，对方尚不能访问我”，不显示虚假的完整成功。每个授权使用独立密钥，不让对方通过自报 NodeId 获得批准。

批准和领取绑定短期 requestId、claim secret、请求方身份及目标权限；配对码一次性、有限有效期和尝试数，沿用已有的限流原则。

NAS 首次授权采用独立的 Node 邀请入口：在 `Bakabase.Service` 宿主新增由管理员显式设置的启动参数 `--federation-invite-on-start`，启用分享且远程访问未关闭时生成一枚限时单次 Node 配对码写标准输出；失败则说明缺少的配置。用户从容器日志读取，超时后可再次显式启动签发。它不复用旧 `FirstDevicePairingCodeAnnouncer` 的 Device 配对码，不受旧设备列表是否为空影响，也不占用只用于开发期代码生成的 `Bakabase.Cli`。首期不新增“旧远程管理员批准 Node 分享”的例外接口；后续需要时另加明确策略。

首期可以将双向流程做成顺序确认，不要求跨机器的分布式事务；断开/重试须幂等。撤销入站授权立即停止后续导出和仍在传输的媒体流，并清理该授权的查询会话。已经传给对方的数据无法远程收回，界面不作这种承诺。

### 6.3 可达性

- 复用 mDNS/UDP 发现与手填地址；发现只提供候选，不自动配对，不扩展访问范围。
- 每节点有 `Online / Offline / Unauthorized / Incompatible / IdentityConflict`；单次查询再记录 timeout、snapshotExpired 等具体结果。
- 在线探测仅对已启用的节点进行，限制并发并退避；应用关闭/禁用时取消。查询不把一次旧探测结果当作本次必然可达。
- 初始建议值：4 路并发、2 秒连接超时、8 秒查询准备期限，均集中配置并由性能验收修正，不散落为多处硬编码。
- `Disabled` 不被配对绕过；分享开关与远程访问开关的组合必须在设备设置页可解释。

```text
PeerCapabilities:

CommonLibraryQuery:

```

`renderedProperties` 带名称、类型、已解析的显示值与来源 scope 信息；不让 A 用自己的 propertyId/tagId 解释 B 的值。字段可读不代表可写。集合只展示来源节点的名称，不写入 A 的集合成员表。

Export DTO 不包含 nodeIds、上游地址、hop count 或任意内部路由；出现这些输入明确拒绝。批量详情只接受本节点 resourceId 和 expectedLibraryEpoch，来源身份由当前节点填充；第三方 ResourceRef 不被转发处理。

新增契约的日期明确使用 UTC ISO 8601 或带单位的数值，枚举使用固定 wire 值，nullable 与未知值规则写入契约。旧 Newtonsoft 时间格式由兼容解析器处理，不能再次用想象的 JSON 编写测试。

新联合协议单独协商版本，不为这项功能提升旧 RemoteAccess 协议版本并拒绝所有旧客户端。节点少一个必需能力就明确排除并给出理由；可选媒体能力按资源降级。

### 7.3 错误与响应约定

新接口统一使用现有响应 envelope，并增加稳定的错误代码、可选 nodeId、retryable 与字段定位信息；不能让前端解析人类可读错误字符串决定流程。GET 分页和媒体授权响应不进入公共缓存。

| HTTP | 代码示例 | 调用方处理 |
|---|---|---|
| 400 | `MalformedQuery`、`InvalidCursor` | 修正请求；不能降级成空筛选 |
| 401 | `InvalidNodeSignature`、`GrantRevoked` | 停止使用凭据，提示重新授权；不匿名重试 |
| 403 | `SharingDisabled`、`CapabilityDenied`、`RemoteAccessDisabled` | 标记来源不可用或权限不足 |
| 404 | `ResourceGone`、`AssetGone` | 保留来源信息并显示不可用，不尝试其他同号资源 |
| 409 | `LibraryEpochChanged`、`QuerySessionInterrupted`、`CursorSuperseded` | 中断当前会话，按具体原因重试或重建查询 |
| 410 | `QuerySessionExpired` | 新建查询；不得透明替换原 snapshot |
| 413 | `RequestTooLarge`、`ResultSnapshotTooLarge` | 限制请求或收窄结果条件 |
| 422 | `UnsupportedQuery`、`ProtocolIncompatible` | 标明不支持的字段/协议，不删除条件后继续 |
| 429 | `Busy` | 根据 Retry-After 有界重试 |
| 503/504 | `ScanBudgetExceeded`、`PeerUnavailable`、`QueryDeadlineExceeded` | 显示来源与预算/超时原因，不返回成功空列表 |

创建联合查询时至少一台成功，可以返回成功页和 `coverageComplete=false`；全部失败返回聚合错误及每节点原因。参与集固定后的翻页失败按上表中断，不用部分页伪装一次成功。

## 8. 搜索语义、排序与正确分页

### 8.1 首期公共查询

首期实现以下明确语义，不直接复用旧 ResourceSearchInputModel 作为跨库协议：

- `text`：去首尾空白后按整段子串匹配，不分词；空字符串等于不限制。对有效 Reserved Name 和文件名分别进行 NFC 后的 ordinal 不区分大小写 contains，二者 OR。有效名称必须使用来源节点既有 scope 选择规则；无文件的占位资源也必须可以通过名称命中。
- `fileAvailability`：`Any / HasFile / MetadataOnly`。它表示资源是否绑定本地文件，不承诺文件此刻可打开；播放时另验可读性。
- `sourceKinds`：与本库 `ResourceSourceLink.Source` 对应，数组内 OR，与 text/fileAvailability 条件 AND；空数组或省略等于不限制。外部作品身份不转换为内容来源；没有 SourceLink 的文件资源来源集合为空，仍能通过 text/fileAvailability 搜到。只接受协议明确支持的来源值，未知值返回错误。
- `sort`：首期支持 `NameAsc / NameDesc`，增加节点身份、库代际和资源数字 ID 作为全序的平局键。暂不支持跨节点“相关度”、随机排序、健康分、按本机自定义属性排序。
- 不支持的字段、操作符、排序、值类型返回 `422 UnsupportedQuery`；不能静默删除条件后继续返回更宽的结果。

原本机库保留全部高级查询功能。联合页中的“名称搜索”与本机的“关键词搜索”文案区分，切换范围不会暗中丢条件。本期不自动把 A 的自定义属性映射成 B 的同名属性。

首期联合摘要的 title 为有效 Reserved Name，缺失时退到文件名；两者都为空则 title=null，界面 displayName 用 `#resourceId` 兜底。查询与排序不使用这个合成 ID 文案，也不套用来源节点的任意显示名模板。这样占位资源、本机/远端语义和排序字段有唯一预期；详情可另外展示来源节点模板名，但不改变当前会话的排序。

### 8.2 节点快照与多路合并

目标：在固定的参与节点与查询会话内，每条结果只出现一次、排序稳定、翻页不会漏项。不能对每台分别取第 2 页后直接拼接，也不能把各库各自的相关度分数当作可比较数值。

实施算法：

1. 协调器固定本次请求的目标节点及查询哈希；本机也通过 `ILocalLibraryReader` 适配参与，但不绕 HTTP 回调自己。
2. 各节点验证完整查询后，一次捕获匹配记录的轻量不可变投影，排序并保存短期快照。快照至少冻结 ResourceRef、显示摘要与排序键；不保存大图和完整详情。
3. 节点返回 `snapshotId`、首块、匹配总数和剩余有效时间。cursor 绑定授权、查询、排序版本与位置，不接受任意跨快照重放。节点 cursor 是不可变数组的定位符，不是一次性消费操作：有效期内同一 cursor 经重新授权后返回相同块，不推进源端消费状态；只有协调器的页位置会事务性推进。
4. 协调器等待到准备期限，将成功节点固定为本会话参与集；失败节点记录在 omittedNodes。迟到节点不插进正在翻页的会话，用户重试覆盖范围会创建新会话。
5. 为每个未耗尽节点保持当前头元素，以统一比较器进行 k 路归并。初始分块建议 128 条，页面建议 50 条，上限 200，最终由测试修正。
6. 一页结果先暂存；所有需要的远端分块成功，且本页涉及的节点通过轻量会话/权限校验后，原子提交该页和所有节点游标。这样不会因本机仍有缓冲就无限延续已撤销的读取资格。校验完成后仍可能发生撤销，承诺是每次请求时检查，不是假装具备跨机原子撤销事务。
7. 未耗尽节点的缓冲用尽而补块失败时，返回 `QuerySessionInterrupted`，保留已展示页，不跳过该节点继续排序，也不提交半页游标。用户可重试或重新查询。
8. 快照过期/节点重启/库代际改变返回 `410 QuerySessionExpired` 或明确的代际错误；不能用实时搜索假冒旧会话的后续页。
9. 用户取消、切换查询、退出页面时释放会话；丢失释放请求依靠 TTL 清理。

各节点快照可以在不同时间创建；首期承诺会话内稳定，不承诺多台数据库同一时刻的事务一致性。详情和播放按点击时的源节点现状读取；资源被删则显示已不可用，不自动替换成另一个同号资源。

### 8.3 本库读取的一致性与成本

现有搜索索引版本不能充当数据库快照标识。首期一致性命名为 `frozen-observation-v1`：在一次有预算的捕获过程中复制必要的资源、属性值、scope 配置和 profile 偏好，生成完整不可变投影后，再对这份投影执行筛选、计数和排序。捕获不同表/缓存可能跨越短时间窗口，返回 `captureStartedAt/captureCompletedAt`；不声称节点内或节点间具有同一数据库事务时点。

实现必须先冻结本次需要的数据与配置，复用既有 scope resolver 的纯解析规则；不能翻一页再重新读一次不断变化的配置，也不能把先拿到的 ID 和后来重新搜索的第 N 页拼起来。后续若要求严格节点内事务快照，再增加专门的事务读取工作包。

首期直接评估捕获的轻量投影，不使用现有“所有 scope 值都进入索引”的结果替代有效名称匹配。索引后续仅作加速：必须证明候选集合不会漏掉投影中的匹配项，再进入优化。发布前以实际规模测试决定是否需要新的轻量投影缓存。

令 L 为被捕获的本库资源数、M 为匹配数、N 为参与节点数、P 为页面大小：节点成本约为 `O(L + M log M)`，捕获工作空间涉及 L，排序后持有的结果快照约 `O(M)`；协调器每页约 `O(P log N)`，缓冲约 `O(N × blockSize)`，不把各节点完整属性表加载到前端。

所有限制集中在配置：节点快照字节数、捕获工作空间、每授权并发会话、全进程预算、查询期限及 TTL。初始建议节点绝对 TTL 10 分钟、汇总会话 5 分钟；汇总到期不晚于任何参与节点，使用剩余寿命和单调时钟，不能假设墙钟完全一致。按内存字节计费，限制单条字符串、解压后响应大小、投影扫描时间；零匹配也不能无界扫描。

预算错误细分为 `ScanBudgetExceeded`（扫描/捕获预算不足，收窄条件未必能解决）、`ResultSnapshotTooLarge`（匹配结果太大，可收窄查询）和 `Busy`（并发预算，稍后重试），统一属于查询未完成。前端展示真实原因，不统一告诉用户缩小关键词；任何一种都不能截断后仍宣称结果完整。

本计划不把“最多显示 2000 条”作为产品约束；小规模 top-K 仅可用在工程原型，不能作为正式分页实现交付。

### 8.4 排序、计数和刷新

- 排序采用 NFC 规范化后 `StringComparer.Ordinal`，大小写敏感；空名称始终最后。`NameDesc` 仅反转名称主键，平局键始终按 NodeId/LibraryEpoch 的规范字符串升序、resourceId 数值升序，避免两端反转规则不同。文本匹配另用 NFC 加不区分大小写的 ordinal contains。协议发布中文、大小写、组合字符、空值及平局的共同测试向量，不依赖 Windows/macOS 的本地文化排序。
- `totalWithinParticipants` 只统计成功快照覆盖的资源记录。它不是去重作品数，也不是全网络总量。
- 部分成功与完整覆盖始终不同显示，例如“已查询 2/3 台，400 条；B 未响应”。
- 节点故障前已成功纳入的快照不能在中途变成 omitted 后偷偷重排。重新选择节点是新查询。
- UI 使用顺序 cursor 和已显示页的本地缓存；首期不提供任意跳到第 999 页。协调器至少缓存最后一次成功的输入 cursor/结果，使丢失响应后的重试幂等；更旧且不再保留的 cursor 返回 `CursorSuperseded`。缓存本身有预算，不无限保存全部页。同页幂等承诺以会话仍有效为前提：缓存命中也先检查权限、代际和 TTL，再重发，不在撤销后用幂等缓存绕过授权。
- 首期联合视图显式刷新，不把各节点完整 SignalR options 流汇入本机。后续可加仅含变更提示的轻量通知，不直接改写现有查询页。

## 9. 详情、媒体与本机动作

### 9.1 资源读取

详情通过 ResourceRef 路由到权威节点，只读 DTO 由来源节点解析属性、显示名、scope、外部身份与集合名称。本机 store 不接收远端 propertyId、profileId、collectionId 作为本机对象键。

导出读取不能触发采集、自动下载、工作流或修改资源属性。允许内部派生缓存，但任何耗时缓存生成须有预算和取消；不能因打开联合结果启动一个跨设备后台业务任务。

### 9.2 媒体资产边界

`assetId` 是来源节点签发的不可猜测标识或有认证的短期描述，绑定授权、ResourceRef、资产种类、允许方法与有效期。源端将它解析为仍属于该资源的可访问资产，并在使用时重新检查资源状态。

客户端不能提交任意服务器绝对路径或任意 URL 换取文件。压缩包条目需要规范化与边界校验；封面、字幕、附件只能来自该资源明确暴露的资产集合。已有任意路径文件接口不作为新只读节点协议的实现后门。

媒体返回流式响应，保留 GET/HEAD、Range、Content-Type、Content-Length、取消和连接关闭语义。读资产之前完成授权，避免公共响应缓存绕过权限。外部链接不由聚合服务器无条件代抓取。

### 9.3 播放策略

1. 优先使用用户为这个来源节点配置的路径映射。新协议使用 `(NodeId, sourceRootId) → 本机根目录`，资源提供经过校验的相对位置，校验拼接及符号链接后的边界、本机文件存在和类型。源端绝对路径不作为资产读取参数。
2. 无映射或文件不可达时，给当前设备播放器受控的本机流地址，由本机代理按对应节点授权取流。
3. 使用本机播放器配置和发现结果，不执行远端传来的程序路径或命令模板。沿用当前主线对 HTTP 流必须找到可用播放器的行为，不把 HTTP URL 交给系统默认浏览器冒充播放成功。
4. 本期重点支持文件型音视频与图片。压缩包流、转码、字幕、多文件批量播放只在各自能力和回归通过后启用；不支持的形态给出原因，不伪装成任意资源均可播放。
5. 可复用当前已安全识别的第三方页面打开能力；远端游戏/可执行文件启动不纳入首期，不能把下载执行隐含到播放里。
6. 本机资源播放继续记录本机历史；远端播放首期不调用源端“标为已播放”写接口。共享播放记录另立协议。

打开目录仅在命中本机路径映射时启用。需要在来源机器打开的窗口不发送到来源机器执行。

## 10. 前端和产品流程

### 10.1 入口与范围

- 原“本机资源”保持原组件、搜索能力和管理行为；新增“全部设备/指定设备”的只读联合视图，视觉上同属资源页。
- 现有安装默认仍进入原本机页。第一次完成设备连接后提示选择是否把全部设备作为默认范围，不自动改变用户工作流。
- 空库启动展示“添加本机资源”和“连接其他设备”两个入口。本机 appOptions 初始化完成即可打开设备管理，不等待任一远端在线。
- 全部设备指本机加用户启用的、直接授权的节点，不是自动查询局域网中一切被发现的程序。

### 10.2 最小改造边界

新增 `FederatedResourceRef`、`FederatedQueryStore`、`PeerStore` 和只读 `ResourcePresentation`。先抽取卡片/详情中不带请求与写操作的展示部分，或新增少量只读组件；不为了首期把全部本机资源 ID 改成联合 ID。

以下地方必须使用完整引用：React key、查询缓存、选中集合、详情路由、封面/播放会话、错误重试、返回列表后的定位。测试必须制造 A、B 各有 `resourceId=1` 的场景。

全局 `BakabaseContextProvider`、`UIHubConnection`、`ProgressorHubConnection` 继续连接本机。任务、设置、语言、播放器配置和主题不会被远端推送覆盖。联合搜索不订阅远端 `/hub/ui` 或旧 `/resource/discovery/stream` 全量数据。

### 10.3 行为表

| 场景 | 首期界面行为 |
|---|---|
| 联合资源卡 | 显示设备名、可用性；名称相同的资源不折叠 |
| 联合详情 | 已解析的只读属性；显示文件是否存在与播放能力 |
| 本机结果需要编辑 | “在本机库中管理”跳回原本机路由 |
| 远端结果的改名/删除/集合编辑/获取资源 | 不提供写操作；后端同样不提供节点权限 |
| 范围切换时已有不支持的高级条件 | 明示哪些条件不能带入；取消切换或经用户选择重置，不能静默丢弃 |
| 部分节点无响应 | 来源状态条保留失败设备及重试操作；结果显示覆盖范围 |
| 查询准备中 | 先显示节点准备状态；参与集合固定后再显示最终有序第一页，不边到达边无提示重排 |
| 翻页中断或会话过期 | 保留现有内容，说明需要重试或刷新，不清空成空库 |
| 资源删除/库代际变化 | 详情显示不可用；不跳到同数字 ID 的其他资源 |
| 一端版本不支持 | 设备仍可管理，显示需升级后才能加入联合搜索 |

所有新增文案同时提供 en/cn。纯客户端专属 `clientMode` 继续用于旧安装兼容；联合视图根据能力与来源判断，不把整个应用伪装成 PureClient。

## 12. 兼容、迁移与发布

### 12.1 产品身份不混用

| 产物 | 过渡期处理 |
|---|---|
| 已有一体版 | 在 `Bakabase` 原安装身份、主程序名、AppData、单实例标识和 feed 上升级，增加联合能力 |
| 已有纯客户端 | 保持 `Bakabase.Client` 身份和独立 AppData；提供迁移说明、统一版下载及配置导出，原连接能力继续工作 |
| Docker | 增加本节点只读导出；不带 Avalonia/客户端宿主，不提供远端调用本机 GUI 的能力 |
| 手机 | 旧签名、配对、资源与播放契约保持兼容；首期不要求手机实现联合协议 |
| 普通远程浏览器 | 保持现有访问方式；首期不能通过 B 的联合界面借用 B 的授权访问 C |

禁止把 `Bakabase.Client` 更新清单指向 `Bakabase` 安装包，也不把新主包直接写入 client 的 CDN 前缀。两个已安装产品仍可同时运行。

统一版继续打包本机 web。旧纯客户端的“不带 web”断言在迁移提示版本仍成立，不为图方便删除。由于共享代码下沉到模块，Service/Docker 的“不含 Client 宿主程序集”断言仍可保留，并增加“不含 Shell/Avalonia”的角色检查。

### 12.2 导入流程

1. 用户在旧客户端导出或在统一版中主动选择旧配置来源；支持旧客户端的独立环境变量和重定向数据目录，不硬编码默认位置。
2. 先展示导入预览。白名单仅包括地址、名称、路径映射提示；旧 ServerId 用作重新握手核对信息。
3. 不导入 DeviceKey、旧管理员凭据、第三方 cookie、旧 appOptions 或整个数据库。路径映射经重新识别的节点/rootId 和本机路径验证后才生效。
4. 每个来源重新申请 node 只读授权；未授权的来源显示待授权，不加入成功查询集合。
5. 重复导入幂等，映射冲突展示选择，不覆盖现有本机库和设置。写新文件原子提交，源文件不移动、不删除。
6. 迁移完成不自动卸载旧客户端。旧浏览器 localStorage/IndexedDB 不整份复制；只有确有需要且有明确 schema 的界面偏好才能逐项导入。

### 12.3 发布顺序

- **内部里程碑 A：**P00–P06，三个真实节点能配对、联合搜索和正确分页，只有开发入口。
- **内部里程碑 B：**P07–P10，打包桌面完成真实浏览/播放/离线恢复；仍同时发布原两种桌面产物。
- **公开测试版：**P11 通过后，在原一体版里提供主动启用的联合能力；文档明确首期边界。
- **迁移版：**P12 提供迁移工具和说明，保留旧端原功能与更新身份。
- **桌面入口收敛：**新能力及迁移在 Windows x64、macOS ARM/Intel 都通过后，下载页默认只推荐统一桌面版；旧客户端继续有迁移和历史下载入口。
- **旧端维护结束：**另行公布最后维护版本/截止日期并达到后才停止；本计划不虚构日期，也不预先删除 updater feed。

涉及 `.github/**`、代码或打包配置的 PR 正常运行 CI；仅本计划等文档变更遵循仓库的文档提交规则。

## 13. 验收矩阵与运行方式

### 13.1 自动化必须验证的行为

| 类别 | 必须覆盖的场景 | 通过标准 |
|---|---|---|
| 真实协议 | 新接口实际 serializer、旧 Newtonsoft 日期、数字/未知枚举、空值、UTC、不同协议版本 | 客户端消费真实字节，不只消费手写桩 |
| 多节点路由 | 三节点各有 resourceId=1；不同密钥/钟差；一端改地址/重装 | 详情、封面、播放与签名全部到正确节点 |
| 身份生命周期 | 重启、升级、库重建、旧备份回滚后复用 ID、克隆为新节点、导入设置 | 身份/代际规则明确；旧引用不命中新库同号资源，旧授权不因恢复复活 |
| 权限 | loopback/Enabled/Unrestricted/Disabled × 匿名/旧设备/新节点/坏签名 | 新导出始终受授权，新节点不能访问管理/Hub/任意文件；旧行为保持 |
| 授权方向 | A→B、B→A、A→B→C、重复请求、领取中断、单向网络 | 不传递信任；状态可恢复，无假双向成功 |
| 查询语义 | 无文件占位、有效 scope 名称、同名属性不同类型、未知过滤、空结果 | 无静默扩大条件，不漏掉合法占位资源 |
| 分页 | 不均匀分布、同名、每块边界、随机数据、多页、修改/新增/删除 | 遍历结果等于快照并集的参考全排序结果 |
| 游标故障 | 响应丢失、NEXT 并发、旧 cursor、到期、节点重启、从 B 补块后 C 失败再重试 | 源端分块可重读，聚合页不重复消费；不返回伪造的“后续页” |
| 部分失败 | 首次一端超时、全部失败、翻页中故障、响应丢失后撤销再重试同 cursor | 覆盖范围准确；翻页不暗中移除参与者；缓存重试同样受权限限制 |
| 预算 | 大量零匹配、巨长文本、大响应、取消、持续建会话 | 内存/CPU/并发受限；取消后工作停止；无静默截断 |
| 资源动作 | 搜索/详情/播放的网络请求清单 | 远端无隐式写 LastSearch/PlayedAt/属性/任务 |
| 媒体 | HEAD、206/416、seek、长流、断连、撤销、路径/符号链接/压缩穿越 | 正确流语义、取消释放、无任意路径访问 |
| UI 隔离 | 两端同 ID/不同标签词典；迟到响应；切范围；全部离线 | 无跨源污染；本机设置、任务、日志可用 |
| 迁移 | 旧一体版/旧客户端/同机双装；环境变量；导入中断重试 | 原数据与 feed 不变；无旧管理密钥导入 |

网络主链路测试至少启动三个真实 Kestrel 宿主，加载实际节点鉴权中间件、导出 controller、本库适配器和 serializer，使用独立临时数据库、端口和数据目录。不能只用返回 200 的假上游证明权限与业务链路；假上游仍可用于传输层故障注入。

宿主启动、AppData 和单实例依赖静态状态的测试必须使用独立子进程，不能在同一进程里反复 Reset 静态变量冒充三台设备。保留现有 `ClientToServerForwardingTests` 的真实传输回归，不把它当作新全链路测试的替代。

### 13.2 真机与打包矩阵

- Windows x64 ↔ macOS ARM/Intel；至少一次桌面 ↔ Docker/NAS；同机运行统一版与旧纯客户端。
- 全新安装、原一体版升级、旧客户端迁移；beta/stable 不串通道；更新后重启仍使用正确数据目录。
- 空本机库、1 万和 10 万级本库、两台大库联合；中文/大小写/重音/长名称/同名项/占位项。

- 使用实际 Avalonia 壳和最终安装包完成一次首启到播放，不以浏览器截图或单元测试替代。

性能记录必须包含：硬件/内存、数据规模、冷/热状态、网络条件、投影捕获与排序耗时、首屏和后续页 p50/p95、请求数、传输量、内存高水位、取消后释放时间。先在 P00 建基准夹具；P11 用这些数据确定默认预算。单台离线增加的等待不超过配置期限；翻页不能重新扫描所有节点全库。

## 14. 风险、观测与发布门禁

| 风险 | 实施措施 | 阻止发布的信号 |
|---|---|---|
| 新只读凭据得到旧管理员权限 | 独立 principal 与管线提前分派，模式矩阵测试 | 任一写接口或 options/Hub 可达 |
| 来源身份丢失 | ResourceRef 贯穿缓存、页面与媒体 | 同 ID 的两设备任意一处串资源 |
| 查询条件变宽 | 严格 DTO 校验，联合页独立条件 | 不支持的筛选被忽略后返回结果 |
| 快照吃满内存 | 字节/工作空间/并发/TTL 预算，取消测试 | 超限仍持续扫描/分配，或默默截断 |
| 翻页重排和漏项 | 固定参与集、全序、k 路合并、原子游标 | 参考排序比对不一致 |
| 播放落到源端或启动远端指定程序 | 本机动作窄入口、只用本机播放器配置 | 来源机器被拉起 GUI 或任意命令 |
| 旧安装升级失败 | 固定包身份/feed/数据根，真实升级矩阵 | client updater 收到 Bakabase 主包，或数据目录被覆盖 |
| 功能“单元测试全绿、真机不可用” | 真实 serializer、三宿主、独立进程、实际安装包链路 | 仅桩测试或仅开发浏览器演示 |

新增日志记录查询 sessionId、脱敏节点标识、阶段耗时、遗漏原因、页序号、预算拒绝和授权撤销。默认不记录搜索原文、资源完整路径、密钥、配对码或媒体票据；不新增未经配置的遥测上传。

公开测试版的准入是 P10 用户场景与 P11 矩阵通过，不以“所有代码已合并”代替可用性。停止推荐纯客户端的准入还包括 P12 迁移通过。
