# 统一多设备管理

本文描述当前多设备管理的产品边界和数据模型。代码、自动测试、实际设备验证与用户验收分别记录，文档不代表已经发布。

旧的只读共享资源库已移除，不保留旧接口、分享授权或兼容入口。日常浏览与管理统一使用管理员配对和原有资源列表；已有的管理配对、路径映射、定义同步及设备身份继续保留。

## 产品边界与数据关系

一体版和纯服务端都可以作为管理者。A 获得 B 的管理授权后，在 A 原有资源列表中搜索和管理 B 的资源，继续使用既有网格、详情、筛选和操作；设备作为筛选条件，远端资源用设备颜色标识。浏览器访问 A 时，查询与跨设备调用由 A 的服务端执行。日常资源管理不要求切换整站视图；一体版原有服务器视图切换仍是可选入口。

管理关系是单向且不传递的：A 管理 B 不代表 B 能管理 A，也不代表 A 能管理 B 连接的其他设备。每个资源仍由所属设备唯一持有，引用始终包含设备身份、库代际和该库内部 ID；名称或路径相同不会自动合并资源。未启用多设备互联时，原一体版本机功能继续使用既有流程。

| 关系 | 实际保存的数据 | 授权与写入边界 |
|---|---|---|
| 数据同步（定义同步） | 自定义属性及选项、扩展名分组，以及合并基线和冲突记录 | 使用 `datasync.read` 读取定义，经同步规则写入接收设备自身的定义表；不通过这套协议复制资源或文件 |
| 管理设备的资源元数据副本 | 按来源隔离的资源元数据、属性值、关联目录和查询索引 | 使用管理员配对；副本供管理者本机查询，编辑仍发往资源所属设备，不把远端资源 ID 导入管理者的普通资源表 |

资源副本不是文件副本，也不是另一份可独立编辑的主库。资源可搜索不保证可播放或可处理：文件访问仍取决于来源在线状态、实际文件路径、路径映射和执行端能力。新增协议要求来源设备升级；旧来源会显示需要升级，不悄悄降级为逐次全库抓取或不完整的成功结果。

## 设备名称与本机可查询的元数据副本

设备名称由设备自身保存，可在获准的管理入口修改；修改时检查用户看到的旧名称，避免覆盖另一端刚保存的名称。改名不改变设备 ID、配对、库代际或路径映射，容器随机主机名也不再是不可更改的用户标识。

管理者为每个来源设备和库代际维护独立的磁盘 SQLite 副本。首次同步分批读取属性等目录、资源及查询所需索引，再追平来源的持久变更日志；页面内容和断点一起提交。后续以增量更新和删除记录追平，不为每次搜索重新请求远端全库。源端导出只包含自身资源，不递归导出它管理的其他设备，也不导出播放器可执行配置、连接凭据或媒体文件内容。

搜索与普通元数据读取在管理者本机执行，沿用现有属性筛选语义；匹配过程分批读取，结果保留在磁盘，不再为远端副本构造常驻的全库内存索引。界面显示首次同步、已同步数量、最后同步时间、暂停、离线和失败等状态。首次同步未完成不会伪装成空媒体库；已有完整副本时，离线仍可查询上次完整内容，但不能据此执行需要来源在线的文件访问或写入。一旦确认授权撤销、设备身份或库代际不匹配，旧副本不再作为可访问的来源返回。

暂停、恢复和进程重启保留断点。新结构代际在旧完整副本旁分批准备，完成后切换，避免读到半份新库。普通编辑仍只向所属设备发送一次；发送前持久保存刷新屏障，提交后先追平副本，尚未追平时明确提示正在刷新，不将旧值显示成保存后的回滚，也不因响应丢失而自动重发编辑。

### 元数据断点与目录修订

资源快照的逐页游标持久保存在管理设备的磁盘副本中。未被资源名称模板引用的属性名称、属性排序以及保留既有引用项不变的标签／单选／多选选项追加，只提高目录修订号；同步会在资源追平后分批重新读取目录，不从头扫描资源。暂停和重启均保留资源游标。目录刷新期间已有完整副本仍可查询，写后读取屏障会等待目录分页完成。

属性类型、选项删除或修改、别名、影响派生值的规则等结构性变化仍切换快照代际并重新扫描；完成前保留旧的完整副本。这一保守边界用于确保原有搜索运算语义正确，不将不兼容的新定义与旧索引混用。

当前目录中的属性名称和顺序在读取资源时按所属设备及属性 ID 补齐，包含嵌套父资源；读取受同一结构代际约束，不改写资源值、别名或名称模板结果。目录分页有大小限制；资源分页、查询、单个资源和索引项也有明确预算，超限返回可诊断错误，不无界扩展内存。

## 可复用范围与独立规则块

资源扩展可以引用一个单独保存的资源范围。范围包含筛选条件及来源设备／库代际，可被多个扩展复用；修改范围不需要逐个重新复制条件。播放器、打开方式、可播放文件等规则作为独立规则块编辑，更新一个块不会用陈旧的完整对象覆盖其他块。范围、绑定和规则编辑带版本检查；冲突提示用户重新读取后处理，正在使用的范围不能被直接删除。

A 上为 B 创建的范围和资源扩展留在 A，不变成 B 的全局配置。来源属性和资源 ID 始终按 B 的身份解释；本机规则不会因为数字 ID 相同而应用到另一设备的资源。未绑定共享范围的既有扩展仍可使用原来的条件和本机执行行为。

## 显式跨设备增强与可播放文件任务

增强和可播放文件处理可显式指定执行设备：资源所属设备、当前管理设备，或指定的已管理设备。管理者按范围扫描资源并协调任务，执行设备读取本次固定的输入和规则进行计算，结果交回资源所属设备验证与写入。文件任务要求执行设备能够访问对应文件；路径映射只转换路径，不自动挂载共享、复制媒体或授予文件权限。纯服务端可以协调或执行其具备能力的任务，并不因此获得桌面播放器启动能力。

资源所属设备是唯一写回方。任务准备固定来源身份、库代际、资源修订和规则；结果应用时再次检查版本及内容，使用比较后写入（CAS）拒绝已过期的计算结果，避免后台任务覆盖期间发生的新编辑。附件按受限块传输并校验，执行端路径不能直接当成来源路径写回。已应用结果通过持久回执识别，重试读取回执而不是再次应用；这些任务的版本保护不等于为所有历史资源编辑接口新增了多主冲突合并。

任务状态、当前阶段、资源游标和步骤进度持久保存。界面可查看进度、等待设备、失败或冲突，并进行暂停、恢复、取消及允许的重试；重启后从已保存的状态继续，已确认写回的步骤不会重复提交。临时结果、附件、文件遍历、任务队列与并发均有预算或清理机制，超限和恢复失败保留明确状态，不能显示为成功。

## 当前不包含的能力

这轮实现的是用户明确选择规则、范围和执行设备后的跨设备任务，不是自动分布式调度：不会根据各设备负载自动选择工作节点、拆分任意现有后台任务、自动安装缺失依赖或搬运整份媒体文件。来源离线时也没有资源编辑离线队列。

设备名、范围／规则和跨设备处理结果已有版本冲突检查；普通资源属性编辑继续遵循原所属设备接口的写入语义，刷新屏障解决读到旧副本的问题，不承诺所有普通编辑都有 CAS 或可自动合并。定义同步与管理员配对保持独立；定义同步不会授予资源管理权限。

## 管理路径映射与草稿

入口为“多设备互联 → 设备与分享 → 管理 → 本机管理的设备 → 路径映射”。每个目标设备单独保存映射：来源前缀是目标设备视角下的路径，本机前缀是执行设备能够访问的路径。树形选择器只聚合目标设备自己持有的资源路径，不包含它管理的其他设备资源；按需加载目录层级和分页，不把全部路径传到浏览器。

路径映射只转换路径，不创建 SMB/NFS 挂载、不复制文件，也不新增权限。浏览器访问 Docker 服务端时，本机前缀指该服务端容器能访问的挂载路径；桌面客户端的本机前缀指桌面所在电脑能访问的目录。

未保存的映射编辑暂存在当前浏览器的本地存储中，按管理者、目标设备和库代际隔离；重新打开可恢复或主动清除。保存时比较当前映射与编辑开始时的值，发现其他窗口已修改会要求重新审阅，不能覆盖别人刚保存的内容。保存成功后清除草稿。树中展示的来源目录不是文件访问授权。

## 实现位置

| 位置 | 内容 |
|---|---|
| `src/modules/Bakabase.Modules.RemoteAccess/Components/Management` | 管理配对、签名请求、连接存储、身份核验和每设备映射 |
| `src/apps/Bakabase.Service/Components/Federation/MetadataReplicas` | 按来源与库代际隔离的磁盘元数据副本、本机搜索、断点与刷新屏障 |
| `src/apps/Bakabase.Service/Components/Federation/Processing` | 跨设备任务的协调、执行、结果校验与恢复 |
| `src/apps/Bakabase.Service/Components/Federation/ManagedLibraryMapping*` | 管理映射树的分页、路径聚合和游标校验 |
| `src/modules/Bakabase.Modules.Federation` | 仍被使用的设备身份、定义同步授权与传输、共用媒体边界 |
| `src/apps/Bakabase.Remoting` | 桌面可选的整站切换中继及本机播放 |
| `src/web/src/features/federation` | 设备管理、设备地图、管理路径映射和草稿 |

服务端 Docker 不带桌面中继、Shell、Avalonia 或 YARP；一体版保留原安装包、数据目录、单实例与更新身份。详见[设备管理与桌面切换](server-switching.md)及仓库的发布契约检查。
